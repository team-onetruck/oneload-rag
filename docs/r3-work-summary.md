# R3(RAG·데이터) 작업 정리 — 팀원용

> **한 줄 요약**: Agent가 "근거를 보고 답하게" 해 주는 검색 모듈(`oneload-rag`)을 만들었습니다. 공식 자료만 모은 안내 문서 13개, 장소 별칭 사전, 검색 평가셋까지 준비했습니다. 백엔드에서 한 줄만 바꾸면 지금의 가짜 검색(Mock) 자리에 그대로 들어갑니다.

## 1. RAG가 우리 서비스에서 하는 일

외국인이 "공항철도 표 어디서 사요?"라고 물으면, Agent(R2)는 바로 답을 지어내지 않고 R3 모듈에 **검색**을 맡깁니다. R3 모듈은 미리 모아 둔 공식 안내 문서에서 관련된 것을 찾아 돌려줍니다. Agent는 그 문서를 근거로 답하고, 화면에는 **출처와 확인 날짜**가 함께 나옵니다.

- 문서에 없는 내용(예: 아직 확인 못 한 버튼 이름)은 Agent가 "확인되지 않음"으로 답합니다.
- 그래서 **문서의 정확성이 곧 답변의 정확성**입니다. 문서는 공식 사이트에서 직접 확인한 내용만 넣었습니다.

## 3. 역할별로 알아야 할 것 · 부탁

자세한 내용과 진행 상태는 [requests.md](requests.md)(RQ-01~29)에 있습니다.

### R2 (Agent)

- **연결:** `search_knowledge(query, language, context)` 모양이 지금 Mock과 같습니다. Agent 코드는 바꿀 필요가 없습니다.
- **장애 처리:** 검색에 장애가 나면 R3 모듈이 Agent의 `ToolUnavailable`로도 잡히는 예외를 던집니다. 그래서 Agent는 그대로 "답 보류(`cannot_answer`)"로 처리합니다.
- **요금 질문:** 이제 요금 문서가 있어서, "직통열차 요금 얼마야?"에 13,000원이라고 **답하는 것**이 정답이 됐습니다. 답할 때 **확인 날짜도 함께** 말해 주세요.
- **도움받을 곳 안내 순서:** 역 안 창구(B3 고객안내센터, B2) → 외국인용 1330 → 공항철도 콜센터 → 분실물·긴급 상황(마지막). 역무실 긴급전화나 콜센터를 먼저 권하지 말아 주세요.
- **기후동행카드:** 2026년 10월부터 국내용 30일권은 끝났고 단기권만 남았습니다. 인천공항역에서는 **내리기만** 되고 타기는 안 됩니다. 직통열차에는 쓸 수 없습니다. 프롬프트나 고정 문구에 예전 내용이 있으면 고쳐 주세요.

### R4 (Backend · 지도)

- **연결:** `app/main.py`에서 `MockKnowledgeSearch()`를 `hangil_rag.search_knowledge`로 바꾸면 됩니다. 코드 예시는 README에 있습니다.
- **DB:** pgvector를 쓸 때는 같은 Postgres의 **`rag` 스키마**만 씁니다. 백엔드 테이블과 섞이지 않고, 백엔드 alembic도 건드리지 않습니다.
- **깨진 출처 URL:** 백엔드와 `oneload-data`가 인용하는 AREX 공식 URL(`…/co/steUsfGud.do`)이 지금 404입니다. 대체 URL은 RQ-01에 있습니다.
- **지도에 반영할 것:**
  - 장소 별칭 사전 (`poi/seoul-station.aliases.yaml`, RQ-27)
  - "도움받을 곳" POI 5곳 (고객안내센터, 트래블센터, 도심공항터미널, 1·4호선 갈아타는 곳, 티머니타운)
- **장소 검색 방식:** 지금은 "질문이 별칭 안에 통째로 있을 때만" 찾아서 긴 질문은 못 찾고, 짧은 별칭이 엉뚱하게 걸릴 수 있습니다(RQ-28).

### R5 (앱)

- 화면 문구에 기후동행카드 30일권이나 예전 이용 범위가 있다면 고쳐 주세요(RQ-21).
- 시스템이 지금 받는 언어는 한국어·영어뿐입니다. 일본어·중국어를 넣으려면 백엔드·Agent·앱을 같이 바꿔야 합니다(RQ-24).

### R6 (QA)

- **QA 정답 근거:** `docs/qa-source-map.md`에 Q01~Q20 근거를 정리했습니다. **Q10(요금)은 "답불가"에서 "답가능"으로** 바뀌어야 합니다.
- **검색 평가:** `eval/`의 평가셋(44문항)으로 검색만 따로 잴 수 있습니다. 임계값은 이 평가셋 기준으로 0.25를 제안했으니 문항을 보태 확정해 주세요(RQ-12).
- **평가 문항 후보:** 여행객이 실제로 막히는 상황 10개를 정리했습니다(`research/community-2026-10-22.md` 4절).

### R1 (PM)

- **CI 토큰:** GitHub 레포 설정에 `TEAM_REPO_TOKEN`(옆 레포 읽기 전용)을 등록해 주시면, Agent·백엔드와의 연결 테스트도 자동으로 돕니다(RQ-14).
- **촬영 허가:** 답사 전에 서울역 촬영 허가를 받아야 합니다. 촬영·개인정보 절차에서 팀이 정할 4가지는 RQ-29에 있습니다.

## 용어 풀이

- **RAG:** 답하기 전에 자료를 먼저 찾아보고(검색), 그 자료를 근거로 답하게 하는 방식
- **pgvector / 임베딩:** 문장을 숫자 묶음(벡터)으로 바꿔 "뜻이 비슷한 문장"을 찾게 해 주는 Postgres 확장. 키워드가 달라도 뜻이 비슷하면 찾음
- **scope:** 문서 종류 표시 (ticket 승차권, card 교통카드, fare 요금, help 도움받을 곳, transit 대중교통). Agent는 요금 질문에 `fare` 문서만 씀
- **확인일(`verified_at`):** 그 문서의 출처를 마지막으로 열어 확인한 날. 요금처럼 바뀌는 정보는 이 날짜를 함께 보여 줌
