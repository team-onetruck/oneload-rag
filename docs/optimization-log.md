# 검색 최적화·개선 기록 (R3)

개선할 때마다 **같은 방법으로 전후를 재서** 여기에 한 줄씩 남깁니다. 검증이나 발표 때 "무엇을 바꿔서 얼마나 좋아졌는지"를 이 표로 설명합니다.

## 재는 방법

```sh
uv run python eval/measure.py                 # 검색 평가셋 · LLM 에 넘기는 발췌 크기 · 메모리 · 검색 시간
set -a; . ../.env; set +a                     # 실제 LLM 확인만 OpenAI 키 필요 (질문 16개, 몇십 원)
uv run --project ../oneload-backend --with . python scripts/agent_live_check.py
```

- 비교할 두 시점(커밋·브랜치)에서 같은 명령을 돌려 아래 표에 적습니다.
- 평가셋: R3 47문항(`eval/retrieval.yaml`), R3 보류 검증 28(`eval/retrieval_holdout.yaml`), R6 32·v2 40(`oneload-qa/eval/`). 숫자는 "정답 상위 3개 / 범위 밖 빈 결과".
- **R6가 판정용으로 고정한 셋(v3 등)은 R3가 돌리지 않습니다.** 결과를 보고 고치면 독립 검증이 안 되기 때문입니다.
- 이미 결과를 본 셋(R3 보류 28, R6 v2)은 회귀 확인용입니다. 이 숫자만으로 "좋아졌다"고 말하지 않습니다.

## 기록

### 1. 범위 밖·실시간 질문 거르기 (RAG #3, 2026-10-23, `320bf1e`·`5482222`)

- 무엇: 질문 정보량 대비 문서가 덮는 비율(`MIN_COVERAGE` 0.25)이 낮으면 빈 결과, "빈 좌석·잔여석" 같은 실시간 질문은 빈 결과, "얼마·how much"는 요금 문서도 찾기. pgvector 검색에도 같은 판정
- 메모리 검색 전후

  | 평가셋 | 전 | 후 |
  | --- | --- | --- |
  | R3 44 | 38/40 · 3/4 | 38/40 · 4/4 |
  | R6 개발 16 | 9/10 · 1/6 | 10/10 · 6/6 |
  | R3 보류 28 (실행 전 고정) | 16/16 · 5/12 | 16/16 · 11/12 |

- pgvector(실제 임베딩) 범위 밖 차단: R6 개발 1/6 → 6/6, R3 보류 5/12 → 11/12. 정답 질문은 그대로
- 한계: R6 v2(독립)에서 오탐 3·누락 3. 문서를 더할 때마다 경계 근처 질문이 흔들림(아래 3)

### 2. 실시간 판정·영어 기능어 빈틈 (2026-10-23, `2ecf338`·`0121496`)

- "seats **are** left" 꼴 실시간 질문을 못 잡던 표현식 수정
- "vs·versus"를 모르는 낱말로 세서 Agent 검색어 "Express vs All-stop difference"가 빈 결과가 되던 것 수정 (범위 점수 0.246 → 기준 위)

### 3. 문서 추가에 따른 흔들림 (2026-10-23, v0.3.0)

- 서울역 환승 문서·약관·이용안내를 넣을 때마다 경계 질문이 오감: R3 보류 범위 밖 11/12 → 9~10/12, R6 32 12/12 → 11/12. 기준값 0.22~0.27을 다시 비교해도 0.25가 최선
- 교훈: 문서를 고치면 `eval/measure.py`를 반드시 다시 돌린다

### 6. LLM 에 넘기는 발췌 줄이기 (`perf/chunk-excerpts`, 2026-10-26, `b151cf7`)

- 배경: 평가 교수 의견 "문서 전체를 올리지 말고 최적화". 메모리 검색은 문서 본문 전체를 발췌로 넘겼고, Agent는 이걸 그대로 LLM 프롬프트에 넣음
- 무엇: 고른 문서 안에서 질문 낱말이 가장 많이 겹치는 `###` 소제목 하나만 넘김. 제목 낱말만 겹치면(문서 전체를 묻는 질문) 본문 전체. 문서 고르는 방식은 그대로
- 전후 (PR #4 → 이 브랜치, `eval/measure.py`)

  | 항목 | 전 | 후 |
  | --- | --- | --- |
  | 평가셋 결과 4개 | (위 5의 "후") | 모두 같음 |
  | LLM 에 넘기는 발췌 (질문당 상위 3개 합계) | 중앙값 3,398자 · 평균 4,032자 · 최대 8,624자 | **중앙값 1,618자 · 평균 1,964자 · 최대 6,283자 (49%)** |
  | 검색기 메모리 | 약 785KB | 약 1,396KB (소제목 색인을 미리 만들어 둠) |
  | 검색 1회 | 1ms 미만 | 1ms 미만 |
  | 백엔드 연결 시험 | 6/6 | 6/6 |

- 남은 것: 문서 전체를 묻는 질문은 여전히 큰 문서(일반열차 운임표 5천 자)를 통째로 넘김. 필요하면 길이 상한을 두는 방안
