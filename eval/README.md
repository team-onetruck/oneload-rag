설계서 5.3 "임계값과 k는 R3·R6가 평가셋으로 정한다"에 쓰는 자료입니다.

- `retrieval.yaml`: 질문 44개(국/영)마다 정답 문서를 정해 둔 평가셋입니다.
  - 출처: QA 평가 문항, 커뮤니티 "막히는 곳", Agent가 실제로 쓰는 검색어, 카드·패스 질문
  - 범위 밖 질문 4개는 아무 문서도 나오지 않아야 정답입니다.
- `retrieval.py`: 상위 3개(Agent가 쓰는 개수) 적중률과 "범위 밖이면 빈 결과" 비율을 잽니다. `--sweep`을 붙이면 메모리 검색 임계값 후보를 비교합니다.

```sh
uv run python eval/retrieval.py            # 지금 설정 (RAG_BACKEND=pgvector 면 pgvector)
uv run python eval/retrieval.py --sweep
```

- **놓친 질문:**
  - "How do I pay?": 너무 짧고 일반적인 질문입니다.
  - "Why was I charged an extra 500 won?": 요금 문서가 아니라 보증금 문서가 나와야 합니다.
- **잘못 걸린 범위 밖 질문:** "명동 가는 버스 번호"에 대중교통 문서가 걸립니다.
- **한계:** 평가셋을 R3 초안 작성자가 만들어서, 이 평가셋에 맞춘 결과일 수 있습니다. R6가 문항을 보태고 확정해야 합니다.
## pgvector + 실제 임베딩 결과 (2026-10-23)

- **조건:** 로컬 pgvector(백엔드 `compose.yaml`의 DB, `rag` 스키마), OpenAI `text-embedding-3-small`(1536차원), 문서 13개 / 72조각
- **실행:** 적재는 `python -m hangil_rag.ingest`, 평가는 `RAG_BACKEND=pgvector uv run python eval/retrieval.py`

| 설정 | 1위 정답 | 상위 3개 안에 정답 | 범위 밖 빈 결과 |
| --- | --- | --- | --- |
| 키워드 메모리 검색 (기본값) | **32/40** | **38/40** | 3/4 |
| pgvector, 키워드 가중치 0.3, 최소 점수 0.3 (이전 기본값) | 27/40 | 37/40 | 2/4 |
| pgvector, 키워드 가중치 0.5, 최소 점수 0.3 (**새 기본값**) | 28/40 | 36/40 | **4/4** |
| pgvector, 키워드 가중치 0.3, 최소 점수 0.2 | 29/40 | 39/40 | 1/4 |

- **결론:** 이 평가셋에서는 키워드 메모리 검색이 pgvector보다 낫거나 비슷합니다. **MVP는 메모리 검색(기본값)을 유지하는 것을 권합니다.**
  - pgvector를 쓴다면 키워드 가중치 0.5, 최소 점수 0.3이 범위 밖 질문을 모두 막으면서 적중을 크게 잃지 않습니다.
  - 평가셋이 키워드형 질문 위주라 키워드 검색에 유리했을 수 있습니다. 문서가 많아지거나 표현이 다양해지면 다시 비교해야 합니다.
- **응답 시간:** pgvector 검색 1회는 질문 임베딩(OpenAI 호출)을 포함해 중앙값 0.18초, 최대 0.28초입니다. 메모리 검색은 0.1ms 미만입니다.
- **비용:** 문서 적재는 1회 72조각(약 3만 5천 자)이고, 그 뒤로는 질문마다 임베딩 호출이 1번씩 생깁니다.

## RAG #3: 범위 밖·실시간 질문 개선 (2026-10-23)

R6가 보고한 문제는 "서울역 근처 호텔 객실 가격", "지금 직통열차 빈 좌석 몇 개"처럼 범위 밖인 질문에 관계없는 문서가 나오는 것이었습니다. 순위 매기기는 그대로 두고 다음 세 가지를 더했습니다.

1. **범위 판정 (`MIN_COVERAGE` 0.25)**
   - 질문의 정보량을 계산합니다. 여러 문서에 흔한 낱말은 가볍게, 문서에 아예 없는 낱말은 가장 무겁게 칩니다.
   - 가장 잘 맞는 문서가 그중 25%도 덮지 못하면 빈 결과로 돌려줍니다.
   - "모르는 낱말"은 낱말 단위로 셉니다. 어미 조각, 의문사, 지시어(이거·여기 등), 영어 기능어는 세지 않습니다.
2. **실시간 구분:** 빈 좌석·잔여석·실시간 등 현황을 묻는 질문은 빈 결과로 돌려줍니다. 근거 문서가 없기 때문입니다.
3. **가격 표현 묶기:** "얼마·가격·how much·price"가 나오면 요금 문서도 찾습니다.

기준값은 R3 44문항과 R6 개발 16문항만으로 정했습니다. 범위 밖 질문의 최고값은 0.242, 정답 질문의 최저값은 0.257이었습니다. R6 보류 검증셋은 설계에 쓰지 않았습니다.

| 평가셋 | 개선 전 (`4a967b3`, 0.25) | 개선 후 |
| --- | --- | --- |
| R3 44문항: 정답 상위 3개 / 범위 밖 차단 | 38/40 / 3/4 | **38/40 / 4/4** (1위 정답 32 → 33) |
| R6 개발 16문항 | 9/10 / 1/6 | **10/10 / 6/6** |
| R6 보류 검증 16문항 (이미 공개됨, 참고용) | 10/10 / 2/6 | 10/10 / 6/6 |
| **새 보류 검증 28문항** (`retrieval_holdout.yaml`, 실행 전 커밋 `6aa035f`로 고정, 1회 실행) | 16/16 / 5/12 | **16/16 / 11/12** |

- **남은 오탐:** "택시 기본요금이 얼마예요?"에 공항철도 요금 문서가 나옵니다. "택시"가 기후동행카드 문서에 있어 아는 낱말로 처리되고, "기본요금"이 요금 문서와 겹치기 때문입니다. 보류 검증 결과라 이걸 보고 고치지 않았습니다. 다음 개선 때 새 질문으로 다룹니다.
- **한계:** 새 보류 검증 질문도 R3가 썼습니다. R6가 따로 만든 새 보류 검증셋으로 다시 확인해야 합니다.
- **pgvector 검색:** 같은 범위 판정을 임베딩·DB 조회 전에 합니다. 범위 밖 질문에는 OpenAI 호출도 하지 않습니다.
  - 순위·임계값은 그대로입니다. 가격 표현 묶기는 메모리 검색에만 있습니다(임베딩이 뜻을 잡음).
  - 실제 임베딩으로 측정(2026-10-23)한 결과입니다. 정답 질문은 그대로입니다.

| 평가셋 (pgvector) | 판정 없음 | 판정 있음 |
